# 即時字幕（本機 CPU）程式架構說明

這份文件說明「程式是怎麼運作的」以及「每個檔案負責什麼」，給想看懂或修改程式的人閱讀。
只想使用程式的話，請看 [使用說明書.md](使用說明書.md)；功能與效能規格見 [功能規格書.md](功能規格書.md)。

> 每個程式檔開頭都有一段說明（docstring），函式內部也有中文註解。
> 建議從 [app.py](../voicetype/app.py) 的 `App` 類別開始讀。

---

## 1. 一句話的旅程

會議中對方說了一句 "Good morning everyone."（講者語言勾了中文＋英文），程式內部依序發生：

| 步驟 | 誰負責 | 做了什麼 | 資料變成 |
|---|---|---|---|
| ① 收音 | `audio.py` `AudioCapture` | 每 30 毫秒從音效卡取一小塊聲音，轉成 16 kHz 單聲道（soxr 重新取樣） | 一小塊音訊 |
| ② 切句 | `segmenter.py` `Segmenter` | WebRTC VAD 判斷每 30 ms 是不是人聲；停頓 0.5 秒（講很久時 0.2 秒）就算一句 | `Utterance`（一句的音訊） |
| ③ 編碼 | `asr.py` `WhisperCpu._decode` | 只把「實際長度＋2 秒」的音訊送進 Whisper 編碼器（不補滿 30 秒） | 編碼結果 |
| ④ 判斷語言 | 同上 `_choose_language` | 用同一份編碼結果偵測語言，只在勾選的語言之間選；中英夾雜 → 當作中文 | 語言 |
| ⑤ 解碼 | 同上 | 產生文字；一直重複同一句時改用 30 秒完整視窗重試 | 文字 |
| ⑥ 整理 | `asr.py`、`filters.py` | 中文轉台灣繁體＋全形標點；去掉重複句與 Whisper 幻覺句 | `Transcription` |
| ⑦ 先顯示原文 | `app.py` → `gui.py` → `overlay.py` | 原文立刻出現在大字幕上 | `result` 事件 |
| ⑧ 翻譯 | `translate.py` `NllbTranslator` | 外語句子拆成單句後用 NLLB 翻成簡體，再用 OpenCC 轉台灣用語 | 中文 |
| ⑨ 補上中文 | `overlay.py` | 同一句換成「中文大字＋原文小字」 | `translated` 事件 |
| ⑩ 存檔 | `output.py` `Output` | 依講話順序寫入逐字稿（原文＋中文） | `transcripts\*.txt` |

### 延遲從哪裡來

| 來源 | 大約多久（i7-1255U） | 怎麼縮短 |
|---|---|---|
| 等講者停頓 | 0.5 秒（`vad.end_silence_ms`） | 調低，但句子容易被切碎 |
| 語音辨識 | 0.5～0.9 秒（長句 1.5～2.5 秒） | `beam_size = 1`、合適的 `cpu_threads`、只勾一種語言 |
| 翻譯 | 約 0.8 秒（600M）／1.4 秒（1.3B） | 用 600M；原文先顯示，翻譯在另一個執行緒 |

CPU 上最慢的一步是 Whisper 編碼器。Whisper 原本不管句子多短都補滿 30 秒再編碼，
本程式改成只編碼實際長度（`asr.dynamic_window`），4 秒的句子從約 4 秒降到約 0.5 秒。

## 2. 執行緒架構

辨識和翻譯都要花 0.5～1 秒以上。全部放在同一個執行緒的話，等待期間就收不到新的聲音，
所以程式拆成多個執行緒，彼此用**佇列**（queue，像輸送帶）傳遞資料：

```
 ┌──────────────────┐ 音訊塊  ┌──────────────┐ 一句音訊 ┌──────────┐ 辨識結果 ┌──────────────────┐
 │ PortAudio 回呼    │ ──────► │ 主迴圈（切句） │ ───────► │   asr    │ ───────► │    translate      │
 │ ＋ audio 看門狗   │ audio_q │  App._run     │  utt_q   │（辨識）   │   mt_q   │（翻譯＋寫逐字稿） │
 └──────────────────┘         └──────────────┘          └────┬─────┘          └────────┬─────────┘
                                                             │ result 事件              │ translated 事件
                                                             ▼                          ▼
                                     ┌──────────────────────────────────────────────────────────┐
                                     │ 介面主執行緒（tkinter）：每 50 ms 取出事件 → 控制視窗、大字幕 │
                                     └──────────────────────────────────────────────────────────┘
```

| 執行緒 | 程式位置 | 工作 |
|---|---|---|
| PortAudio 回呼 | `AudioCapture._open` 的 `callback` | 收到音訊 → 重新取樣 → 放進 `audio_q`（滿了就丟，避免延遲累積） |
| `audio` | `AudioCapture._run` | 每秒檢查裝置：串流中斷、麥克風 3 秒沒資料、Windows 預設裝置換了 → 自動重新連接 |
| 主迴圈 | `App._run`（介面模式在 `voicetype` 執行緒） | 從 `audio_q` 取音訊、更新音量表、切句、暫停處理、錄 WAV |
| `asr` | `App._asr_worker` | 辨識 → 送出 `result` 事件 → 放進 `mt_q` |
| `translate` | `App._mt_worker` | 需要時翻譯 → 送出 `translated` 事件 → **唯一**寫逐字稿的執行緒（順序正確） |
| `hotkey` | `hotkey.py` | Windows 全域快捷鍵（RegisterHotKey 訊息迴圈） |
| `download-watch` | `app.py` `_DownloadWatcher` | 第一次下載模型時，每秒量 `models\` 長大了多少，回報進度 |
| 介面主執行緒 | `gui.py` `ControlWindow._poll` | tkinter 只能在這個執行緒操作；每 50 ms 取出事件更新畫面，單一事件出錯不會讓更新停掉 |

背景執行緒**不直接碰** tkinter 元件，只把 `(事件種類, 內容)` 放進 `ControlWindow.events` 佇列。

### 事件一覽（`App` → 介面）

| 事件 | 內容 | 介面的反應 |
|---|---|---|
| `status` | 文字 | 寫進辨識結果區；「載入…」「🎙 開始收音」「🔄 已重新連接」會更新狀態燈 |
| `progress` | 下載進度文字（空字串 = 完成） | 顯示在狀態燈 |
| `result` | `Transcription`（原文） | 結果區＋大字幕新增一句 |
| `translated` | `Transcription`（含 `translation`） | 結果區加中文；大字幕該句換成中文＋原文 |
| `paused` | 是否暫停 | 按鈕文字與狀態燈 |
| `level` | 音量（dBFS），每 0.1 秒 | 音量表 |
| `pending` | 等待辨識的句數 | 「辨識中 N 句」 |
| `error` | 錯誤訊息 | 紅字；需要網路時跳出提示視窗 |
| `stopped` | — | 恢復成可設定狀態、隱藏大字幕 |

## 3. 資料夾與檔案說明

```
cpu-subtitle/
├─ voicetype/            程式本體（Python 套件）
├─ tests/                自動測試（pytest，不需要模型和音效卡）
├─ packaging/            打包設定（PyInstaller）、exe 進入點、給使用者的使用說明
├─ scripts/              setup.ps1（安裝）、run.ps1（執行）、build_exe.ps1（打包）
├─ docs/                 本文件、使用說明書、打包與部署、功能規格書
├─ config.example.toml   設定範本（第一次執行時複製成 config.toml）
├─ requirements.txt      套件清單
└─ start.bat             雙擊開啟控制視窗（不顯示主控台）
```

執行後才會出現（不進 Git）：`.venv\`、`models\`、`transcripts\`、`logs\`、`config.toml`、`build\`、`release\`。

### 3-1. 進入點與主流程

| 檔案 | 說明 |
|---|---|
| `__main__.py` | `python -m voicetype` 的進入點 |
| `app.py` | 命令列參數、`main()`、`App`（主流程與執行緒）、`run_file`（音檔測試）、`run_benchmark`（CPU 測速）、`_DownloadWatcher`（下載進度） |

### 3-2. 設定

| 檔案 | 說明 |
|---|---|
| `config.py` | 每個區段一個 dataclass（`AudioConfig`、`VadConfig`、`AsrConfig`、`TranslateConfig`、`OutputConfig`、`OverlayConfig`、`HotkeyConfig`）；`load_config` 讀 TOML（格式錯誤或型別錯誤時改用預設值並記錄警告）；`save_config` 只改數值、保留註解；`apply_language_policy` 由「講者語言」推算辨識方式；`app_root` 決定資料存放位置 |

### 3-3. 收音與切句

| 檔案 | 說明 |
|---|---|
| `audio.py` | `AudioCapture`：PyAudioWPatch 開啟麥克風／WASAPI loopback；`Mixer` 兩者混音；`Resampler` 轉 16 kHz；裝置編號失效時改用預設；看門狗自動重新連接 |
| `devices_win.py` | 用 ctypes 呼叫 Windows Core Audio（`IMMDeviceEnumerator`）取得目前預設喇叭／麥克風的 ID，偵測使用者切換預設裝置 |
| `segmenter.py` | `Segmenter`：VAD 狀態機（等待說話 ↔ 句子進行中）；停頓結束、講太久時短換氣就切、超過上限在最安靜處切開並把剩下的接到下一句 |

### 3-4. 語音辨識

| 檔案 | 說明 |
|---|---|
| `asr.py` | `WhisperCpu`：faster-whisper（CTranslate2）CPU INT8；動態視窗、單次編碼＋語言偵測＋解碼、重複輸出時改用完整視窗重試、中英夾雜規則、台灣繁體轉換、模型優先用本機檔案 |
| `filters.py` | Whisper 幻覺句過濾（「ご視聴ありがとうございました」等）、重複句合併 |

### 3-5. 翻譯

| 檔案 | 說明 |
|---|---|
| `translate.py` | `NllbTranslator`：NLLB-200（CTranslate2 INT8）；先拆句再批次翻譯；簡體→OpenCC `s2twp`；半形標點轉全形 |

### 3-6. 輸出與介面

| 檔案 | 說明 |
|---|---|
| `output.py` | 逐字稿寫檔 |
| `gui.py` | `ControlWindow`：控制視窗（兩個分頁）、事件迴圈、設定存檔、裝置清單、CPU 測速 |
| `overlay.py` | `SubtitleOverlay`：無邊框、最上層、不搶焦點（`WS_EX_NOACTIVATE`）的大字幕；圓角（`SetWindowRgn`）；自製右鍵選單 `_PopupMenu` |
| `hotkey.py` | 全域快捷鍵 |

### 3-7. 啟動流程

```
start.bat / LiveSubtitle.exe
  └─ main()
       ├─ 關閉 hf_xet（下載時才看得到進度）、沒有主控台時把輸出導到 logs\voicetype.log
       ├─ load_config()  ← config.toml（不存在就從 config.example.toml 複製）
       ├─ apply_language_policy()
       └─ run_gui() → ControlWindow
            └─ 按「開始字幕」→ App(cfg).run() 在背景執行緒
                 ├─ 載入（必要時下載）Whisper 模型、翻譯模型
                 ├─ AudioCapture.start()（先確定收得到聲音）
                 ├─ 建立逐字稿、註冊快捷鍵、啟動 asr／translate 執行緒
                 └─ 主迴圈：收音 → 切句 → utt_q
```

停止後再開始時，模型、精度、執行緒數沒變的話會**沿用已載入的模型**（`WhisperCpu.can_reuse`）。

## 4. 重要觀念

- **只編碼一次**：`WhisperModel.transcribe(language=None)` 會為了偵測語言先跑一次編碼器、辨識時再跑一次。
  這裡用同一份編碼結果做「偵測語言＋解碼」，和 faster-whisper `multilingual=True` 的做法相同，
  但每一句都偵測，而且只在勾選的語言之間選。
- **動態視窗**：CTranslate2 的 Whisper 編碼器接受短於 30 秒的輸入（等同 whisper.cpp 的 `-ac`）。
  補白太少時短句容易重複輸出，所以至少保留 5 秒；仍然重複時自動改用 30 秒視窗重試。
- **語言規則**：只勾一種語言就固定用它；勾多種時，短句信心不足會沿用上一句的語言（必須是勾選的語言）；
  判成英文但中文機率 ≥ 0.15，或結果裡有漢字 → 當作中英夾雜。
- **NLLB 先翻簡體再轉繁體**：NLLB 的簡體中文訓練資料多很多，直接輸出繁體時長句容易被截斷。
- **模型優先用本機檔案**：先用 `local_files_only=True` 載入，失敗才連網下載；所以第二次以後不需要網路。
  下載改用一般 HTTP（關閉 hf_xet），檔案邊下載邊寫入，才量得到進度。
- **資料位置**：預設在程式所在資料夾；不能寫入或路徑超過 90 字元時改用 `%LOCALAPPDATA%\LiveSubtitle`
  （模型快取路徑本身就約 150 字元，Windows 預設上限 260 字元）。

## 5. 想改某個功能，要看哪裡？

| 想改 | 看哪裡 |
|---|---|
| 斷句時機 | `config.toml` `[vad]`；邏輯在 `segmenter.py` `_process`、`_split` |
| 語言判斷規則 | `config.py` `apply_language_policy`、`asr.py` `_choose_language`、`transcribe` |
| 換辨識模型的預設 | `config.py` `AsrConfig.model`、`config.example.toml`、`gui.py` `MODELS` |
| 換翻譯模型 | `gui.py` `MT_MODELS`、`app.py` `MODEL_SIZES_MB`（下載百分比用） |
| 字幕外觀與預設樣式 | `overlay.py` `PRESETS`、`apply`、`_place` |
| 控制視窗版面 | `gui.py` `_build_dictation_tab`、`_build_overlay_tab` |
| 逐字稿格式 | `output.py` |
| 幻覺句清單 | `filters.py` `_EXACT`、`_CONTAINS` |
| 自動重新連線的時機 | `audio.py` `WATCH_INTERVAL_S`、`MIC_STALL_S`、`RETRY_S`、`_problem` |

## 6. 測試與檢查

```powershell
scripts\setup.ps1 -Dev                # 安裝 pytest
.venv\Scripts\python -m pytest        # 21 項自動測試，不需要模型和音效卡
scripts\run.ps1 --file 音檔.wav --languages zh,en   # 用真的模型測一段音檔
```

自動測試涵蓋：切句（停頓、短換氣、硬切不掉字）、幻覺與重複過濾、標點、混音、語言規則與「上一句語言」、
設定檔讀寫（保留註解、格式錯誤、型別錯誤）、逐字稿順序、資料夾規則、快捷鍵解析、自動重新連線的判斷。
