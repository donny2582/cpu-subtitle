# 即時字幕（本機 CPU）

參考 [donny2582/live-subtitle](https://github.com/donny2582/live-subtitle)，改成**完全在本機 CPU 執行**的即時中文字幕：

> 講完一句 → 停頓約 0.5 秒 → 整句字幕跳出。中文（含中英夾雜）直接顯示；英／日／韓翻成中文並附原文。
> 講者一直講不停時，會在換氣處主動斷句，不會一直累積。

**下載**：到 [Releases](https://github.com/donny2582/cpu-subtitle/releases) 下載 `LiveSubtitle.zip`，解壓縮後雙擊 `LiveSubtitle.exe`（不需要安裝 Python）。

**文件**：

| 文件 | 給誰看 |
|---|---|
| [使用說明書](docs/使用說明書.md) | 使用者：安裝、操作、常見問題 |
| [功能規格書](docs/功能規格書.md) | 功能需求、實測效能與準確度、參數、限制 |
| [程式架構說明](docs/程式架構說明.md) | 開發者：資料流程、執行緒、每個檔案負責什麼 |
| [打包與部署](docs/打包與部署.md) | 打包成 exe、在其他電腦使用、更新版本 |

| 項目 | 做法 |
|---|---|
| 收音 | 系統聲音（會議軟體、YouTube、影片）、麥克風，或**兩者混音** |
| 斷句 | WebRTC VAD 偵測停頓（預設 0.5 秒）；講超過 4 秒後短短換氣就斷句，8 秒還沒停就在最安靜處切開 |
| 辨識 | faster-whisper `small`，CPU INT8，**只編碼實際長度**（不補滿 30 秒） |
| 語言 | 勾選講者可能講的語言（中／英／日／韓）：只勾一種 = 固定該語言；勾多種 = 每句在勾選的語言之間判斷 |
| 翻譯 | NLLB-200（Meta 多語翻譯模型）CTranslate2 INT8，翻成簡體後用 OpenCC 轉台灣繁體用語 |
| 字幕 | 無邊框、永遠在最上層的大字幕視窗：中文大字、原文小字；預設灰色半透明、圓角，樣式可調 |
| 紀錄 | 逐字稿（原文＋中文）一律存檔，可選擇另存 WAV 錄音；沒有語音輸入打字功能 |
| 隱私 | 不需要 GPU、網路、API 金鑰（只有第一次下載模型需要網路），聲音與文字不會離開電腦 |

## 安裝

需要 Windows 10/11、Python 3.11 以上。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
```

## 使用

雙擊 **`start.bat`**（或執行 `scripts\run.ps1`）開啟控制視窗，按 **▶ 開始字幕**。
第一次會下載模型：語音辨識 small 約 470 MB，有勾英／日／韓時再加翻譯模型約 600 MB。

### 「辨識與翻譯」分頁（執行中不能改）

- **講者語言**：勾選講者可能會講的語言（中文／英文／日文／韓文）。
  - **只勾一種**：固定用那個語言辨識，最快也最準。例如只勾中文，就不會把中文短句誤判成日文。
  - **勾多種**：每句只在勾選的語言之間自動判斷，沒勾的語言不會被偵測。
  - **中文、中英夾雜**（「這個 deployment 我們明天再 review」）→ 直接顯示，不翻譯。
  - **英／日／韓** → 翻成中文，字幕上中文大字、原文小字對照。
  - 有人講了沒勾的語言時，會被硬套成勾選的語言辨識而變成錯字，所以要把可能出現的語言都勾上。
- **收音來源**：系統聲音（會議、影片）／麥克風／兩者混音，可各自選裝置。混音時請戴耳機，
  否則喇叭的聲音會被麥克風再收一次。
- **翻譯模型**：快（NLLB 600M，約 0.8 秒／句）或準（NLLB 1.3B，約 1.4 秒／句，用詞較自然）。
- 停頓出字毫秒數、是否另存 WAV 錄音、CPU 執行緒、beam、提示詞。
- 「測試 CPU 速度」會找出這台電腦最快的執行緒數並自動填入。

### 「字幕外觀」分頁（隨時可改、立即套用）

樣式（預設灰底白字；另有黑底白字／白底黑字＋黑框／黑底黃字／黑框黑底白字，或點色塊自訂）、字型、字級、粗體、
外框粗細、圓角大小、透明度、同時顯示幾句、寬度、距螢幕底部、幾秒後清除、語言標籤、**中文下方小字顯示原文**、滑鼠點擊穿透。
「預覽字幕」可先看效果。

字幕視窗可以直接拖曳；在字幕上按右鍵可放大／縮小字、清除、重設位置、隱藏；`Ctrl + 滾輪` 也能調字級。
外語句子會先顯示原文，翻譯好後換成「中文大字＋原文小字」。

按「儲存設定」會把兩個分頁的設定寫回 `config.toml`（保留原本註解）。

快捷鍵（任何視窗都有效）：`Ctrl+Alt+F9` 暫停／繼續、`Ctrl+Alt+Q` 停止。可在 `config.toml` 的 `[hotkey]` 修改。

### 命令列（不開視窗）

```powershell
scripts\run.ps1 --cli                                  # 只有中文，結果印在終端機
scripts\run.ps1 --cli --languages zh,en,ja             # 講者可能講中／英／日；英日翻成中文
scripts\run.ps1 --cli --source both --languages zh,en  # 系統聲音＋麥克風混音（請戴耳機）
scripts\run.ps1 --list-devices                         # 列出麥克風／系統聲音裝置編號
scripts\run.ps1 --benchmark                            # 測出這台 CPU 最快的 cpu_threads
scripts\run.ps1 --file meeting.wav --languages zh,en   # 用音訊檔測試辨識＋翻譯
```

用 `start.bat` 開啟時沒有主控台，錯誤訊息寫在 `logs\voicetype.log`。

## 速度

在開發這台 **Intel i7-1255U 筆電**（15 W、背景開著瀏覽器與會議軟體）實測，從「講完一句」算起：

| 階段 | 時間 |
|---|---|
| 原文字幕出現 | 約 0.3～0.8 秒（含 0.5 秒停頓判斷） |
| 中文翻譯出現 | 約 0.9 秒（NLLB 600M） |
| 長句（11～15 秒） | 辨識約 1.5～2.5 秒，因為解碼時間和字數成正比 |

做法重點：

1. **只編碼實際長度**（`dynamic_window = true`）：Whisper 原本不論句子多短都補滿 30 秒再編碼，
   這是 CPU 上最慢的一步。CTranslate2 其實接受較短的輸入，只編碼「實際長度＋2 秒、至少 5 秒」，
   4 秒的句子編碼從約 4 秒降到約 0.5 秒（等同 whisper.cpp 的 `-ac`）。補白太少時短句會重複
   （「好的好的好的」），所以保留至少 5 秒。
2. **只編碼一次**：同一份編碼結果同時用來偵測語言和解碼。
3. 辨識 `beam_size = 1`（實測準確度相同）；翻譯 `beam_size = 2`（設 1 時日韓會翻錯）。
4. 辨識和翻譯在不同執行緒，原文先出、中文再補上，下一句的辨識不用等翻譯。
5. 翻譯時先依句號拆句再一起翻（NLLB 是用單句訓練的，整段丟進去常漏翻）。

## 斷句

| 情況 | 何時出字幕 |
|---|---|
| 講完停頓 0.5 秒 | 立刻 |
| 一句講超過 4 秒 | 下一個 0.2 秒的換氣就斷句 |
| 講到 8 秒都沒換氣 | 在最近 1.5 秒內最安靜的地方切開，剩下的接到下一句（不會掉字） |

實測把 3 句英文（約 18 秒）頭尾相接、完全不停頓地播放，會被切成 3 段（各 5～7 秒），都切在換氣處。
可在 `config.toml` 的 `[vad]` 調整 `soft_cut_s`、`soft_end_silence_ms`、`max_utterance_s`。

還想更快：停頓出字調到 350～400 ms（句子較容易被切碎）；Intel 12 代以後的大小核筆電先跑「測試 CPU 速度」。
`large-v3-turbo` 較準但在這台筆電明顯較慢，不建議用在即時字幕。

## 打包成應用程式（給沒有 Python 的電腦）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

產出 `release\LiveSubtitle\`（約 230 MB）與 `release\LiveSubtitle.zip`（約 94 MB）。把 zip 給對方，解壓縮後雙擊
`LiveSubtitle.exe` 即可，不需要安裝 Python、Visual C++ 或其他套件（Windows 10／11 64 位元）。

- **模型不打包**：第一次按「開始字幕」時自動下載到程式旁邊的 `models\`（語音辨識約 470 MB；有勾英／日／韓再加翻譯約 600 MB），
  狀態列顯示下載百分比。之後開啟直接使用，不需要網路。
- 第一次使用沒有網路時，會跳出提示請使用者連網。
- 程式放在沒有寫入權限（例如 `C:\Program Files`）或路徑太長（超過 90 字元）的資料夾時，
  模型、設定、逐字稿改存到 `%LOCALAPPDATA%\LiveSubtitle`（避免超過 Windows 260 字元的路徑上限）。
- 沒有數位簽章，第一次執行 Windows 可能顯示「Windows 已保護您的電腦」：按「其他資訊」→「仍要執行」。
- 給使用者看的說明：`packaging\使用說明.txt`（會一起放進發布資料夾）。

## 已知限制

- 這是「準即時」：講完一句才出字，講話中途不會顯示。
- 本機翻譯（NLLB）品質比雲端大型模型差一些，偶爾會漏翻或用詞生硬；需要較好品質可換 1.3B 模型。
- 多人同時說話只會辨識較大聲的一方，也不區分講者。
- 只有漢字的日文短句可能被判成中文。
- 強制斷句時，一個完整的句子可能被分成兩段字幕，翻譯也會分成兩段。
- 執行中拔掉耳機／麥克風、或切換 Windows 預設喇叭／麥克風時，會在約 1 秒內自動重新連接
  （控制視窗顯示「🔄 已自動重新連接：裝置名稱」；暫時沒有裝置時每 2 秒重試）。
  例外：在設定裡**指定了某個裝置**（不是「系統預設」）而且它被拔掉時，會改用系統預設裝置。
- 依賴 PyAV 16 以下（faster-whisper 1.2.x 和 PyAV 17+ 不相容，`requirements.txt` 已鎖定）。

## 專案結構

```
voicetype/
├─ app.py         進入點：命令列參數、主流程（收音 → 切句 → 辨識 → 翻譯 → 字幕／逐字稿）
├─ gui.py         控制視窗（tkinter）
├─ overlay.py     大字幕視窗（無邊框、最上層、不搶焦點、可拖曳）
├─ config.py      config.toml 讀取與存檔（保留註解）、語言規則
├─ audio.py       擷取系統聲音／麥克風／兩者混音，重新取樣到 16 kHz、斷線自動重新連接
├─ devices_win.py 讀取 Windows 目前的預設喇叭／麥克風（偵測切換）
├─ segmenter.py   VAD 切句
├─ asr.py         faster-whisper CPU INT8：動態視窗、單次編碼、語言判斷、繁體轉換
├─ translate.py   NLLB 本機翻譯、全形標點
├─ filters.py     Whisper 幻覺過濾
├─ output.py      逐字稿
└─ hotkey.py      全域快捷鍵
tests/            pytest（不需要模型、音效卡）
packaging/        PyInstaller 設定、exe 進入點、給使用者的使用說明
scripts/          setup.ps1、run.ps1、build_exe.ps1（打包）
```
